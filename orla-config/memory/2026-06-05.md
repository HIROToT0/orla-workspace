## cron 路径错误修复（08:03）

HIRO 早上 8:00 报告"cron job 没正常执行"。

### 根因
系统 crontab 里 `run_daily.sh` 的路径**缺了 `/skills/`**：

```
# 错的（每天 07:00 静默失败）
0 7 * * * .../workspace/szex-bid-notice-sync/scripts/run_daily.sh
# 对的
0 7 * * * .../workspace/skills/szex-bid-notice-sync/scripts/run_daily.sh
```

不是新错——06-04 早上那次也没跑成，但当时 watchdog 7:30 发了告警之后，HIRO 早上 8:00 来问，我手动补跑了两次（这就是 cron.log 里 08:04:20 + 08:04:55 两条"开始抓取任务"标记的来源），掩盖了路径错误。**06-05 同样失败，HIRO 又来问，这才暴露。**

watchdog 那条路径是对的（带 `/skills/`），所以它每天 7:30 都能跑、能发飞书告警——但告警只在"07:00 主任务缺标记"和"07:30 watchdog 检测"两个时间点之间有效，凌晨发出去没人看，加上 weekend 没人值守。

### 修复
1. 备份原 crontab → `/tmp/crontab.backup.20260605-080313`
2. 修路径，加 `/skills/`，`crontab` 装回
3. 手动补跑今天 06-05 任务：08:03:17 完成，0 新增（数据已被前几天抓过），飞书简报已发

### 教训 / 待加固
- **crontab 路径拼写错误是静默杀手**——cron 不会大声报错，文件不存在就直接跳过；watchdog 只能事后发现。
- watchdog 自愈逻辑没问题：今天 7:30 写了告警 state，等主任务跑成功后下次 watchdog 会清掉。✅
- **建议：写一个路径自检脚本，每天/每周校验 `crontab -l` 里所有可执行路径都真实存在**。比 watchdog 提前一步——文件一被改错就告警，不用等到 7:00 cron 跑失败再发现。
- skill 装在 `workspace/skills/<name>/`，但 SKILL.md/exec 习惯写 `workspace/<name>/`——名字一致容易复制粘贴出错。下次装/移 skill 后用 `realpath` 校验一次。

## 路径自检脚本 check_cron_paths.py 已上线（08:11）

### 设计
- 独立脚本 `scripts/check_cron_paths.py`（不和 watchdog 混，关注点分开：watchdog 查"运行时标记"、这个查"配置正确性"）
- 解析 `crontab -l`，提取每行命令第一个 token（必须以 `/` 开头）
- 只查**脚本本身**是否存在，不查 `>>` 重定向的 log 路径（log 不存在时 shell 会自动创建，那不是 bug）
- 同一天去重：缺失路径集合变了（修了旧的又丢了别的）会重报
- 自愈：路径补回来后自动清 state + 记 `healed_at`

### 挂载
~~每 30 分钟一次，轻量~~ 改为不开 cron，改 crontab 时手跑校验（HIRO 反馈：路径写错是"改的时候"就错的，不是运行中崩，30 分钟轮询没意义）
```
# 删掉了：
# */30 * * * * .../check_cron_paths.py ...

# 改 crontab 后手跑：
python3 .../scripts/check_cron_paths.py
```

### 现在的 cron 全貌
```
0   7  * * * run_daily.sh        # 主任务
30  7  * * * watchdog.py         # 主任务缺标记告警（事后兜底）
```
check_cron_paths.py 留作手验工具（不开 cron）。

### 教训（HIRO 反馈）
- **过度设计警告**：路径写错是写入时的 bug，不是运行时漂移——30 分钟探活=无意义轮询。HIRO 一句话打回："只要脚本正常了就不需要每 30 分钟一次吧"。✅ 接受。
- 应该问"问题什么时候发生"再决定探活频率：写时错 → 写入时校验；运行时崩 → 频繁探活；外因触发 → 事件驱动。
- 类似地：watchdog.py 7:30 跑也够用——路径错导致 7:00 静默失败，7:30 watchdog 发"主任务没跑"告警覆盖了同一症状。

### 测试（已通过）
- 2a 故意把 run_daily.sh 路径改回错版本（缺 `/skills/`）→ 飞书告警 + state 写入 ✓
- 2b 再跑一次 → 去重跳过 ✓
- 2c 改回正确路径 → 自愈清 state + `healed_at` 记录 ✓

### 现在的 cron 全貌
```
0   7  * * * run_daily.sh        # 主任务
30  7  * * * watchdog.py         # 主任务缺标记告警（事后）
*/30 * * * * check_cron_paths.py # 路径配置正确性（事前，30 min 一次）
```

### 教训
- 这次比 06-04 那次有用了——06-04 早上路径错的 30 分钟内没人告警，拖到 7:30 watchdog 才发，再拖到 8:00 HIRO 来问；现在改了 30 分钟内飞书就响
- "**事前 vs 事后**" 自检组合：check_cron_paths 抓配置层（cron 触发前），watchdog 抓运行时（cron 触发后），run_daily 抓业务层（数据抓取）
